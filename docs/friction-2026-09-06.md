# Removing caller bookkeeping

The ordinary loop still asked the working model to maintain too much of the
memory system. This pass used the existing roles and stored game history to
identify failures, then changed the implementation.

- Replacing a scoped lesson without repeating metadata cleared its scope.
  Corrections now preserve omitted metadata; replacement scope and clearing
  are explicit. MCP supports the same behavior and allows metadata-only repair
  without making the model repeat the original lesson body.
- Searching old wording found a superseded game-design preference but provided
  no path to its differently worded replacement. Historical inspection now
  includes the latest successor separately. Stale writes still fail and point
  to the record to inspect; they do not overwrite it automatically.
- Short references stopped at receipt and signal surfaces. Generated guidance,
  brief, state, state-link, recall and tool inspection handles now use them too.
- The common protocol repeated identity and unrelated capability recipes.
  Identity appears once; state/tool instructions accompany delivered state/tools.
  Ordinary capsules omit closure bookkeeping while retaining immediate
  correction, optional reflection, delegation and data boundaries.
- Recalled observations looked current despite describing old behavior. Their
  recorded dates and originating episodes are now available, with historical
  evidence kept separate from present task instructions and artifacts.
- Review uncovered an older dependency bug: narrowing a compiled source's
  scope left its old globally applicable brief active. Body, kind or metadata
  changes now invalidate the dependent cache in the replacement transaction.
  Unchanged content and scope retain coverage. Historical receipts remain intact.

These repairs make the existing relationship graph consistent with current
knowledge. [The context graph direction](context-graph.md) distinguishes what
already exists from the next useful relationships. General semantic relevance
and contradiction handling still depend on the working model.
