# Retrospective: learning through the Soccer Chess studio

The objective is a persistent named role that gets better through ordinary use. Nine-tails supplies its context and durable operations; the working model still decides what to learn. Soccer Chess is real product work through which to find friction in that flow.

## What is working

The framework and game pools loaded their own roles from the shared store, used the maintained game-check capability, and exchanged current artifacts. Returning game roles surfaced and applied prior guidance about visible player names and matching controls to available actions. Direct loads now include the learning protocol, bounded relevant recall and executable tool recipes. Corrections take effect without compilation; source handles allow exact replacement.

Explicit child metadata now replaces the corresponding inherited keys. The game pool stopped receiving framework reminders after a project switch. Replacing duplicate role status with an authoritative workshop state removed conflicting deployment and test-count snapshots.

The game has five introductory lessons, varied reproducible attack/defense practice, and post-play passing and interception evidence. Automated checks cover the rules and interface interactions. They do not establish enjoyment, learning transfer, or usability on the child's device; live play remains the next source of evidence for those claims.

## What remains awkward

A prose pointer prevents duplicated state, but every fresh specialist must still remember to fetch it. The capsule can be complete enough to work only after an extra lookup. This should be an explicit stored relationship resolved by nine-tails, not another instruction repeated in each role.

The game's old hint returns the original solution regardless of the current board. It can reveal too much at the start and offer stale advice after an alternative move. Coaching should begin with a concept, then offer an optional next legal action based on the current position. Search limits must be distinguished from proven dead ends.

Handled bootstrap broadcasts were still pending after many loads. Their useful content is already in repository instructions and the capsule protocol. The coordinator acknowledged those three known notices through normal lease/ack operations, retaining their history and removing their repeated context cost. This is deliberate reconciliation of known obsolete notices, not automatic aging of arbitrary signals.

## This round's decisions

Add explicit one-hop state links. A role owns the link; the project owner owns the current value. Loading resolves the current target under both applicability scopes, labels it as data with owner/name and version, and accounts for what was shown. A missing link target is visible and repairable without preventing the role from loading. Imports preserve the reference, not a copied foreign state.

Replace static solution dumps with progressive, current-board coaching. A conceptual nudge remains available without solving the board for the player. An explicitly requested next step must be legal and supported by a winning continuation; otherwise offer honest recovery guidance. Reset, undo and mode changes must not leave old hints on screen.

Keep changes grounded in concrete failures. Do not claim general autonomous learning: recording and semantic reconciliation still depend on the working model; compilation is optional; recall is lexical; the MCP adapter still requires host configuration. Do not infer human playtesting from automated checks.

The user's feedback identified another barrier: opaque context and signal IDs
make the interface hard to follow. Add automatic stable local references,
displayed with agent and task/subject. `refs --meta repo-id=soccer-chess` groups
project work using existing scope, avoiding a separate naming ceremony or an
ambiguous “latest” session. Keep canonical IDs for portability and preserve
kind checks after alias resolution.

Validation this round includes 21 game-rule tests, 10 React interaction tests,
a production-worker response check, a production build and TypeScript checking.
The framework review found and repaired YAML parsing that accepted only the
first document; shared state must satisfy the same complete-document contract
as state writes. Framework tests use temporary stores. These are correctness
checks, not evidence of a child's experience playing the game.
