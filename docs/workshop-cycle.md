# Learning while building Soccer Chess

The product objective is a better persistent agent definition: the user's preferences, useful experience and capabilities should follow a named role into ordinary work. A companion can explore or play without manufacturing a correction. The session's work is to improve this cycle through real collaborating agents, rather than evaluate whether a capsule improves a benchmark score.

## Two working pools

The framework pool develops nine-tails. The game studio develops a playable Soccer Chess prototype in `~/projects/soccer-chess`. Its designer owns deterministic rules and scenarios; its engineer owns interaction and presentation; a fresh playtester reviews their handoff. Each starts with a nine-tails load, not a hidden static subagent definition. Both pools use the user store, while project-specific state and lessons have separate repo-id scope.

## Friction addressed

- A direct role capsule previously taught correction syntax without the full learning flow. Every role now gets concise capture, reconciliation and handoff guidance; zero writes is valid and closure does not gate learning.
- Recall required the model to know the history existed. A concise task now retrieves a few matching observations automatically, explicitly labeled as historical evidence with full-record retrieval paths. Important operating guidance is never displaced by recall.
- Tool advertisement required reconstructing the call interface. Tool sections now include an exact receipt-specific call template. The game studio's shared game-check capability invokes the current project's maintained rules test command.
- A summary could hide its source even when its scope excluded it from a particular load. Capsule assembly now falls back to source guidance when its applicable representation is unavailable. Subsequent compaction also receives original source wording.
- Native tool access required a host integration. The optional stdio MCP adapter exposes stable context, learning, inspection, state, discovery and execution operations. It retains explicit receipts instead of changing connection-wide agent identity.

## Operational boundaries

This is contextual learning, performed by the working model through durable operations. It does not watch unobserved conversations or update model weights. Lexical recall is bounded, deterministic and inspectable; it is not semantic retrieval. More capable retrieval can be added when real work exposes misses. The MCP adapter must be connected by the host before its operations become native tools. No mandatory compiler or resident agent loop is introduced.

The checked-in spec and DESIGN describe the resulting behavior. Runtime tests use temporary stores. Game rules and scenario solutions receive normal functional tests, and concrete play defects feed repairs and concise role memories.
